# Releasing AppPilot

[Back to README](../README.md)

AppPilot uses Semantic Versioning. The first public release is `v0.1.0`.

AppPilot 0.1.0 is a source-only release. The GitHub Release contains the
repository source generated by GitHub and no unsigned prebuilt macOS binaries.

## Prepare locally

1. Move relevant entries from `Unreleased` into a dated version section in
   `CHANGELOG.md`.
2. Confirm dependency licenses and update `THIRD_PARTY_NOTICES.md`.
3. From the intended release commit, run the complete local gate:

```bash
make clean && make verify && make clean
```

4. Confirm `git status --short` is empty after the gate. Do not tag a dirty
   worktree.
5. Push the verified commit and confirm the required `CI / verify` check passes
   on `main`.

## Exercise the release workflow

Before creating a tag, run the Release workflow from the Actions tab with
`workflow_dispatch` against the verified commit. This is a manual dry run: the
`verify` job runs the complete gate, while the tag validation and `publish` job
are skipped. It must not create a GitHub Release.

Before making the repository public, configure private vulnerability reporting,
Dependabot alerts and security updates, secret scanning, and branch protection
requiring `CI / verify`. Disable force pushes and branch deletion for `main`.
After the repository is public, rerun the manual dry run and confirm its result
is visible before publishing the tag.

## Verify a clean clone

Verify the public commit from a clean temporary directory so ignored files and
local caches in the working copy cannot affect the result:

```bash
set -euo pipefail
release_tmp="$(mktemp -d "${TMPDIR:-/tmp}/AppPilot-release.XXXXXX")"
trap 'rm -rf -- "$release_tmp"' EXIT
git clone --branch main --depth 1 https://github.com/ggyy0515/AppPilot.git \
  "$release_tmp/AppPilot"
cd "$release_tmp/AppPilot"
make clean && make verify && make clean
test -z "$(git status --short)"
```

`mktemp -d` creates a unique directory, and the quoted `trap` removes only that
directory when the shell exits. Do not replace it with a shared or hand-written
temporary path.

## Tag and publish

Return to the original clean worktree. Create the final annotated tag only after
the local gate, CI, manual dry run, repository settings, and clean-clone check
have passed, then push that tag:

```bash
test -z "$(git status --short)"
git tag -a v0.1.0 -m 'AppPilot v0.1.0.'
git push origin v0.1.0
```

Release tags are immutable. If validation or publication fails after a tag is
pushed, fix the problem and use a new patch version. Never move, replace, or
force-push an existing release tag.

The tag push runs the same `verify` job, validates that the semantic version tag
points at the checked-out commit, and creates a GitHub Release only after
verification succeeds.

## Check the published release

After the tag workflow succeeds, inspect the `v0.1.0` GitHub Release and confirm
it is source-only: it should have generated release notes and GitHub's source
archives, with no attached AppPilot executables, binary archives, or checksum
manifest.

Finally, verify the published tag again in a new clean temporary directory:

```bash
set -euo pipefail
release_tmp="$(mktemp -d "${TMPDIR:-/tmp}/AppPilot-v0.1.0.XXXXXX")"
trap 'rm -rf -- "$release_tmp"' EXIT
git clone --branch v0.1.0 --depth 1 https://github.com/ggyy0515/AppPilot.git \
  "$release_tmp/AppPilot"
cd "$release_tmp/AppPilot"
make clean && make verify && make clean
test -z "$(git status --short)"
```

The trap cleans the temporary clone on exit. Record the workflow and Release
URLs, not local build artifacts, in the release checklist.
